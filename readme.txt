MainGenerate:
	- Generates a new diagram according to the configuration_file and saves it in output_file.
	- configuration_file is the file configuring how the parameters for the generation
	- output_directory is the directory where the generated diagrams are stored (must be created beforehand)
	- num_files is the number of diagrams that are generated
  
	Usage:
		MainGenerate configuration_file output_directory num_files
	Example:
		configuration_files/generated_diagram/test_risk/diagram_generator_configuration_file_P2_30 diagrams/P2_30/P2_30 30
		This generates 30 diagrams in the directory diagrams/P2_30/P2_30 and according to the parameters in diagram_generator_configuration_file_P2_30

-----------------------------------------------------------------------------------------------------------------------------------------

Configuration file for the generations:
	- Located in /DECR/configuration_files/generated_diagram/test_risk

	Structure:		
		- number of participants
		- number of mutable tasks
		- reliability of fixed nodes for each participant
		- energy consumption of fixed nodes for each participant
		- business value of categories
		- reliability of communication tasks between participants
		- energy consumption of send tasks between participants
		- energy consumption of receive tasks between participants

-----------------------------------------------------------------------------------------------------------------------------------------
MainRunAlgorithm:
	- Runs algorithm from a previously generated diagram file
	- The results are outputted to the results directory with the diagram's names
	- diagrams_directory is the directory with the diagrams
	- configuration_file is the file configuring how the parameters for the algorithm
	- from_generated_file (True or False) indicates if the diagram_file is a file that was auto-generated by MainGenerate
	- algorithm_mode (d or r) is the algorithm for applying the decentralisation for the diagrams (d) or simply analysing risk and cost
		and output to the console (r)
	- num_runs how many runs will be performed for each diagram in the directory

    Usage:
        MainRunAlgorithm diagrams_directory configuration_file from_generated_file algorithm_mode num_runs

	Example:
		diagrams/testeV6.5 configuration_files/run_configuration_file_SA2 false d 1
		This applies the decentralisation methodology 1 time to the diagrams in diagrams/testeV6.5 with the parameters in 			configuration_files/run_configuration_file_SA2

Configuration file for the algorithm
	- Located in /DECR/configuration_files
	- Currently only Simulated Annealing (SA) works
	- The same optimisation algorithms supports various strategies regarding the evolution of the algorithm (the default and working is 0) 

	Structure:
		- optimisation algorithm
		- strategy
		- temperature
		- cooling rate (on the code is 1 - this value)
